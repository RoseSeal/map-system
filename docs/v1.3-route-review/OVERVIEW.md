## Positioning

当前系统的建议能力集中在会遇避让（advisory 与 chat agent），本船自身的计划航线不存在：Wuhan 演示中本船航线硬编码在模拟器内，后端无航线对象，`ARCHITECTURE.md` §十 的 `plannedRoute` 为 null。武汉航道局持续发布的航标变动通告也未进入系统。

本版本要回答并落地的一句话问题：**一条航线建议能否做到“生成可验证、适用条件可复核、依据可追溯”——航点由确定性规划器基于真实航道数据给出，适用条件由工具逐项复核并显式声明未复核项，每条依据都能回溯到通告原文或工具结果。**

分工原则（贯穿三个 step）：

- **LLM 不产生坐标与几何。** LLM 只做意图理解、参数选择、工具编排与解释；航点、命中区域、叠加几何全部由程序或工具产出。
- **命中与复核为确定性计算。** 航线与航标的相交、偏航判断、预计接近时间均由程序计算，不交给 LLM。
- **抽取与换算分离。** LLM 只从通告原文抽取坐标原文串与字段依据片段；度分秒到十进制的换算与校验由程序完成，依据片段须在原文快照中逐字可查。
- **未复核条件显式声明。** 武汉段无水深数据（S-57 仅覆盖 Jamaica Bay）、无桥梁净空数据，复核结果必须列出这些未复核的适用条件，不得隐含已复核。

继承的前提：

- 本船身份沿用 `ais.own-ship-mmsi` 单船配置；风险主链路（CPA/TCPA、会遇、评分、轨迹预测）语义不变，本船 CPA 仍按现有方式计算，不消费计划航线。
- advisory 触发与去重沿用 ADR-016，不修改；agent loop 沿用 `AgentLoopOrchestrator` 有界循环与快照隔离约束。
- LLM 默认路由沿用智谱 `glm-4.5-air`（关闭 thinking）。
- 演示航线为合成航线，不构成航行指导。

## Version-Level Definition of Done

1. **通告数据可复现**：固定发布日期区间内武汉航道局全部航标通告（含航标失常通告与无坐标条目）的 HTML 快照、抽取结果、校验结果与航标状态推演结果入仓，并声明快照覆盖截止时间；未通过校验或无法匹配到已收录航标的条目标记为待人工复核，不上图、不参与命中。
2. **抽取评测成表**：至少 5～10 条通告逐条目逐字段人工核对，样本须包含无坐标的状态变更条目（撤除、按里程调整、失常）；报告字段级与总体正确率、换算坐标相对正则解析基准的偏差、航标匹配正确率、待复核条目及原因。
3. **计划航线为系统对象**：后端持有当前生效的本船计划航线（航点带转向半径，航段带左右偏航限与航速），可经接口读取；武汉演示中模拟器本船与后端使用同一航线来源，本船沿该航线航行。
4. **航标上图与航线提醒可演示**：前端显示航标通告图层；本船沿航线前方在前瞻时域内经过有效航标的缓冲范围时，前端出现与 advisory 区分的提醒卡片，内容含航标名称、动作、预计接近时间、通告来源与原文依据。
5. **航道规划可复现可评测**：航道网格由入仓脚本从 `segments.parquet` 可复现构建，网格产物入仓。评测网格只使用 `train` 划分，`val` 用于调参，`test` 只用于最终评测；规划航线与 `test` 中同起终点区域的真实航迹对比，报告平均横向偏差与航线落在历史航道内的比例（报告指标，不设分数门槛）。演示用网格可使用全量数据，须与评测网格分别标识，评测结论只引用评测网格。
6. **对话规划闭环**：chat agent 模式下，用户给出起终点与意图，agent 调用 `plan_route` 与 `check_route` 得到附复核结论（含未复核条件）的候选航线；用户显式采纳后，该航线成为当前计划航线并驱动第 4 项的提醒；工具调用的入参与结果摘要在前端可见。
7. **几何只来自工具**：chat 回复与 advisory 中的地图展示内容只能引用工具产出的叠加几何标识，引用不存在的标识会被校验拒绝；`evidence_items` 为带来源工具字段的结构化对象，前端可从证据联动高亮对应几何。
8. **回归与文档**：现有前后端测试全部通过；度分秒换算、校验规则、航线命中、规划器与叠加引用校验各有针对性测试；`EVENT_SCHEMA.md`、`ARCHITECTURE.md` 与 ADR 随各 step 同步更新。

## Non-Goals

### 本版本不做（deferred，后续版本可做）

- 施工 / 管制 / 限速 / 禁锚等区域型约束（多边形、有效期），以及海事局航行通告数据源。
- 无坐标位置描述的空间解析（航道里程、地名、水道名不换算为坐标）与高斯投影坐标。无坐标条目仍用于更新已收录航标的状态，见 step-1 约束。
- 定时爬虫与运行时 LLM 抽取：通告采集为人工触发的一次性快照，抽取为离线批处理。
- 武汉段水深复核与桥梁净空复核：缺少数据源，仅在复核结果中声明为未复核条件。
- 时间 / 油耗等目标优化与多候选航线排序：规划器给出单条可行航线。
- 计划航线进入风险主链路（如本船沿航线预测参与 CPA/TCPA），以及用航道网格过滤上岸预测轨迹（[`../TODO.md`](../TODO.md) §2「航道约束建模」「轨迹预测特征引入地图/水文先验」）：本版本的航道网格可作为其数据基础，但不在本版本接入。
- 现有图层（风险、CPA 弧线、预测轨迹、海图等）迁移到叠加层机制。
- 航线编辑 UI（拖拽航点等）、多本船 / 船队。
- `evaluate_maneuver` 转向动力学与组合机动（[`../TODO.md`](../TODO.md) §3 相关条目）。

### 本版本不做（never，跨版本边界）

- 由 LLM 直接生成航点坐标、区域边界或任何上图几何。
- 将航线命中、偏航判断或坐标换算交给 LLM。
- 为演示伪造通告日期或篡改原文；演示日期需求通过演示时间参数或“已失效 / 已撤除”状态呈现。

## Step Breakdown

### step-1 航线模型与航标通告提醒

- **目标**：建立本船计划航线对象，并把武汉航道局航标通告转为可上图、可命中的结构化数据，完成“航标上图 → 本船驶近 → 提醒卡片”闭环。
- **输入依赖**：武汉航道局航标通告网页（公开）；现有 Wuhan 演示模拟器与 risk SSE 通道。
- **交付物**：
  - 通告快照、离线抽取、校验与航标状态推演流程及其结果文件；抽取评测表。
  - 计划航线数据模型与读取接口；航标通告 GeoJSON 接口。
  - 航线命中判断与新增提醒事件（risk SSE），`EVENT_SCHEMA.md` 同步。
  - 前端航标通告图层（按动作着色、点击查看原文摘录 / 抽取字段 / 设置时间）、当前计划航线显示、独立于 advisory 的提醒卡片。
  - 模拟器本船改为多航点航线并与后端共用航线来源。
- **Step-level DoD**：版本 DoD 第 1～4 项成立；新增测试覆盖度分秒换算、校验规则与航线命中；现有测试全部通过。
- **约束**：
  - LLM 只抽取坐标原文串与各字段依据片段；换算由程序完成；依据片段须在快照中逐字可查。
  - 航标状态由覆盖区间内按时间排序的全部条目推演，包括无坐标条目；无坐标条目按航标名称与所在水道匹配已收录航标，无法匹配时记入待复核。
  - 状态分为：有效（以最新坐标为准）/ 位置待复核（最近一次位置调整无坐标）/ 失常（漂失等）/ 已撤除。只有“有效”参与空间命中；其余状态不得以旧坐标触发航标存在类提醒，前端以对应状态展示。
  - 前端与提醒标注快照覆盖截止时间；截止时间之后的变更视为未知。
  - 缓冲半径默认 200 m、前瞻时域默认 60 min，均可配置；前瞻沿航线剩余航段计算，不做直线外推。
  - 同一航标在同一次接近中只提醒一次，状态独立于 `SceneRiskStateTracker`。
  - 模拟器现有对遇 / 追越航段与两艘目标船保持不变，新增航段经卫星图确认位于水域内。
- **范围上限**：只处理武汉航道局航标通告（航标优化调整与航标失常），覆盖一个固定发布日期区间，须含 2026-09-24 通告中汉口水道 / 武汉二桥附近虚拟航标；只有一条当前生效航线；不做航线编辑；不接入 advisory agent。

### step-2 AIS 航道规划与航线复核工具

- **目标**：基于真实内河 AIS 历史通航构建航道网格与确定性规划器，并以 agent 工具暴露“规划”与“复核”，使用户可在对话中得到并采纳一条附复核结论的计划航线。
- **输入依赖**：step-1 的航线模型、航标通告数据与命中计算；`trajectory-service/runtime/dataset/segments.parquet`（本地数据，不入仓）。
- **交付物**：
  - 可复现的航道网格构建脚本、网格产物与构建清单（参数、数据来源、统计摘要）。
  - 确定性规划器：起终点 → 航点序列，偏航限由历史航道横向分布导出。
  - agent 工具 `plan_route` 与 `check_route`；复核项为航标通告命中与偏离历史航道，结果显式列出未复核条件。
  - chat 采纳流程：候选航线经用户显式采纳后成为当前计划航线。
  - `AGENT_STEP` 增加工具入参与结果摘要，前端可展开查看（承接 TODO §4）。
  - 规划评测报告；`EVENT_SCHEMA.md` 与 ADR 同步。
- **Step-level DoD**：版本 DoD 第 5、6 项成立；规划器与复核工具有针对性测试；现有测试全部通过。
- **约束**：
  - LLM 只向工具传递起终点、意图参数与待复核航线标识，不传递或改写航点坐标。
  - 航线采纳必须由用户显式触发，agent 不得自行替换当前计划航线。
  - 航道网格只由历史 AIS 统计得出，不引入人工标注航道。
  - 评测网格与演示网格按 DoD 第 5 项隔离；`split` 沿用 v1.2 的按船划分（MMSI 取模），三个划分覆盖同一约 11 天时段（2022-05），评测报告须注明该划分不衡量跨时段泛化。
- **范围上限**：覆盖范围限于 v1.2 数据集的武汉包围盒；单条航线，不做多候选排序；复核条件限于航标通告与历史航道两类。

### step-3 工具几何叠加与结构化证据

- **目标**：让 agent 给出建议时能在地图上指示依据：工具产出的几何以统一标识下发，回复与 advisory 只引用这些标识，证据带结构化来源并可联动高亮。
- **输入依赖**：step-1、step-2 的几何产出（计划航线、航标命中、复核结果）；现有 `evaluate_maneuver` 工具与 advisory 输出解析。
- **交付物**：
  - 叠加几何协议：标识、几何、来源工具、展示类别；chat 回复与 advisory 可引用。
  - 引用校验：引用不存在或非本轮工具产出的标识时拒绝。
  - `evaluate_maneuver` 结果附机动后本船预测航迹几何（沿用瞬时机动假设）。
  - `evidence_items` 结构化（文本、来源工具、来源类型、可选几何标识），后端解析校验、前端展示与 `EVENT_SCHEMA.md` 同步（承接 TODO §3）。
  - 前端通用叠加图层与“证据 → 几何”联动高亮；`ARCHITECTURE.md` §六 / §八 中动画指令条目更新。
- **Step-level DoD**：版本 DoD 第 7 项成立；引用校验与结构化证据解析有针对性测试；现有测试全部通过。
- **约束**：现有 `[source: hydrology]`、`[source: historical_case]` 的溯源要求在结构化后语义不弱化。
- **范围上限**：几何产出方限于 `plan_route`、`check_route`、航标命中与 `evaluate_maneuver`；不迁移现有图层；不做动画时间轴或通用绘图工具。

## Sequencing Constraints

- step-2 的航道网格构建只依赖 `segments.parquet`，可与 step-1 并行；规划器与复核工具须在 step-1 的航线模型与命中计算定型后接入。
- step-3 的叠加协议须在 step-2 工具输出结构稳定后定稿，避免协议返工。
- 外部截止 2026-11-30：step-1 与 step-2 构成最小完整演示；时间不足时优先裁减 step-3，而不是压缩 step-1 / step-2 的校验与评测。
- 每个 step 引入的协议变更须在该 step 内同步 `EVENT_SCHEMA.md`，不跨 step 补写。

## Open Questions

- **规划器运行形态**（step-2 决定）：倾向在 `map-service` 进程内运行、读取离线构建的网格产物，不新增 sidecar；理由是网格搜索计算量小、避免新增部署依赖。不确定性在于网格分辨率与内存占用，需 step-2 实测后确定。
- **航线下发给模拟器的方式**（step-1 决定）：模拟器启动时读取共享航线文件，或从后端接口拉取当前计划航线。step-2 的采纳流程要求后者或等价机制。
- **武汉航道局辖区校验包围盒取值**（step-1 决定）：需覆盖辖区内全部通告点，取值为近似，须在抽取说明中注明。
- **提醒范围是否限定近期变动**（step-1 决定）：是否只对设置 / 调整时间在一定天数内的航标提醒，或对数据集内全部有效航标提醒。
- **失常航标是否单独提醒**（step-1 决定）：失常航标不按“航标存在”命中；是否在其最后已知位置提供“航标失常，注意识别”类提醒，需结合原文“恢复后不再另行通告”造成的状态不确定性决定。
